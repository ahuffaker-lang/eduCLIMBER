# eduCLIMBER Assessment Converter (macOS)

A native Mac app that reshapes a **Running Records** reading-assessment export
into the 15-column CSV that eduCLIMBER's upload expects.

Pick the export → choose the assessment window and school year → the app validates
every row and writes the eduCLIMBER file. Swift + AppKit, built with Xcode, with no
third-party dependencies (`.xlsx` files are read directly).

## Getting the app

**Option 1 — download a build (no Xcode needed).** Every push to a build branch
runs the *macOS app* workflow on GitHub. Open the repository's **Actions** tab,
click the most recent green run, and download the `eduCLIMBER-Converter-macos`
artifact. Unzip it and drag `eduCLIMBER Converter.app` into `/Applications`.

**Option 2 — build it yourself:**

```bash
./scripts/build_app.sh          # tests, builds, signs, produces build/eduCLIMBER Converter.app
```

**Option 3 — Xcode.** `File > Open…`, select `Package.swift`, choose the
**eduCLIMBER-Converter** scheme, and press Run (⌘R). `⌘U` runs the tests.

### First launch

The app is signed ad-hoc, not with a paid Apple Developer certificate, so macOS
treats it as coming from an unidentified developer. The first time only:
**right-click the app → Open → Open**. After that, double-clicking works normally.
(Opening it by double-click first shows a dialog with no Open button — that is
Gatekeeper, not a broken build.)

Requires macOS 12 or later. The downloaded build is universal (Apple Silicon and
Intel).

### The icon

`Resources/AppIcon.icns` is generated by `scripts/make_icon.py` (needs Pillow:
`pip install pillow`) and committed, so building the app doesn't require it. To
change the artwork, edit the drawing code in that script and re-run it — the
shapes and colours are all in one function.

## Source file

CSV or Excel, with these columns. Header text is matched case-insensitively and
ignoring punctuation and spacing, so `reading_level` or `READING LEVEL (A-Z)`
are fine:

| Column | Notes |
|---|---|
| The student name | either one `Student` column in `"Last, First"` form, **or** separate `First Name` and `Last Name` columns — whichever your export has |
| `Student ID` | required |
| `Grade Level` | `K`, `1` … `8` |
| `Reading Level (A-Z)` | `Below A`, `A`–`Z` |
| `Proficiency Level` | passed through as-is |

### What counts as an "Excel" file

The app works out what a file is from its contents, not its name, because
assessment systems label exports loosely. All of these open:

- a real `.xlsx` / `.xlsm` workbook — including one renamed to `.xls`
- an **Excel 97-2003 binary `.xls`** (the old format many systems still export)
- an HTML table saved with an `.xls` name (a very common web export)
- an Excel 2003 XML Spreadsheet, also usually named `.xls`
- CSV, TSV, or any delimited text, with any extension or none at all

No re-saving required. A password-protected workbook is the one thing that
cannot be read, and the app says so: remove the password in Excel and save it
again.

The file picker does not grey anything out — if a file can be read, you can
select it, and anything unreadable is explained when you open it.

### Either name format

Assessment exports split the student name differently, so the app takes either
shape and works out which one it is:

- a single `Student` column holding `Gomez, Maria`, or
- separate `First Name` and `Last Name` columns holding `Maria` and `Gomez`.

Nothing to configure — it detects the columns and fills eduCLIMBER's
`Student First Name` / `Student Last Name` either way. If a file happens to have
both, the already-split columns win (no parsing, nothing to guess), and the
combined column fills in for any row where they're empty. A file with neither
gets a plain message saying it needs one shape or the other, rather than an error
on every row.

Note that a combined column still has to use the comma (`Last, First`). A name
written `Maria Gomez` is flagged rather than guessed at, because splitting on the
space silently mangles multi-word surnames like `Van Dyke`.

`samples/sample_running_records.csv` (combined) and
`samples/sample_running_records_split_names.csv` (split) are small examples to
try it on.

### When a column is misnamed or misspelled

The app never guesses at a header it doesn't recognize. If a column is misspelled
(`Readng Levl (A-Z)`) or renamed (`Rdg Level A-Z`), a **Match Columns** sheet asks
which column in your file holds each expected one, with the closest header
pre-selected — accept it or pick another from the menu. Choose
`— not in this file —` for a column that genuinely isn't there (only allowed for
optional columns). One file column can't be assigned to two expected columns.

Your choices are remembered for that file, so re-converting after changing the
window or school year doesn't ask again. **Match Columns…** in the main window
opens the same sheet any time, including when everything matched automatically —
useful for checking a column wasn't matched to the wrong header.

## What it produces

15 columns, in this exact order:

```
Assessment Group, Assessment Name, Assessment Window, School Year, Student ID,
Student First Name, Student Middle Initial, Student Last Name, Date of Birth,
Student Grade Level, Score Detail 2, Reading Level, Score Detail 1,
Proficiency Level, Score
```

- `Assessment Group` is always `Running Records`, for both languages.
- `Assessment Name` follows the Language prompt: `Independent Reading Level` for
  English, `Independent Reading Level Spanish` for Spanish — they are separate
  assessments in eduCLIMBER.
- `Student Middle Initial` and `Date of Birth` are always blank.
- `Score Detail 2` / `Reading Level` hold the same value, and so do
  `Score Detail 1` / `Proficiency Level`. That duplication is what the eduCLIMBER
  import format wants — it is not a bug.
- `Score` comes from the reading-level table (`Below A` → 1, `A` → 2, … `Z` → 27,
  `Z+` → 28, `MAX` → 29). The table lives in `Sources/EduClimberKit/ReadingLevels.swift`;
  `Resources/Data_Table.csv` is the same data as a reference file, and a unit test
  fails if the two ever drift apart.

### Benchmark scoring (Proficiency Level)

`Proficiency Level` / `Score Detail 1` is not just passed through from the
source file — it is computed from the district's benchmark rubric (Reading
Level × Grade × Assessment Window), using whichever rubric applies to the
batch's Language and School Year:

- A **blank** value in the source file is filled in with the computed score,
  silently — that's the normal case.
- An **existing** value that already matches the computed score is left as-is.
- An existing value that **disagrees** is overwritten with the computed score,
  and the row gets a **benchmark notice** — informational, not blocking. The
  row still converts and exports; the notice is just the chance to see why the
  value changed.
- A grade outside **Kindergarten–5**, and **Kindergarten in Trimester 1**
  specifically (no rubric scale exists for either), is never excluded. The
  row exports with whatever Proficiency Level the sheet already had — blank
  if it had none — and a **benchmark notice** explains that it wasn't
  scored. Real files turn up grades the rubric doesn't plan for (a 6th
  grader in a Spanish file, for example), and dropping the row would just
  push the manual work this app exists to remove back onto the user.

Which rubric applies depends on Language and School Year:

- **Spanish** uses one table, regardless of year.
- **English** uses one table for **2025–2026 and earlier**, and a different
  one for **2026–2027 and later**.

The main window shows a persistent `Benchmark: {table} · Grades K-5 scored,
other grades pass through` line
that updates as you change the Language and School Year prompts, so the
applicable table is visible before you convert. Converting a school year past
a dated rubric's own year (e.g. 2028–2029 against the 2026–27 table) shows a
confirmation dialog, since that table is being carried forward rather than
replaced by something built for that year.

The rubric tables live in `Sources/EduClimberKit/BenchmarkRegistry.swift` and
`Sources/EduClimberKit/BenchmarkRubric.swift`, sourced from the district's
rubric sheets; `Resources/Benchmarks/*.csv` are the same data as reference
files, and a unit test fails if the two ever drift apart. Adding a new year's
table means adding another `BenchmarkRubric` entry with its
`effectiveFromYear` — no other code changes.

### File naming

English and Spanish batches share a trimester and a school year, so the language
is part of the name and the two files sit side by side rather than overwriting
each other:

```
Running_Records_English_Trimester2_2026-2027_educlimber.csv
Running_Records_Spanish_Trimester2_2026-2027_educlimber.csv
```

The pattern is editable in the **Saved File Name** box, which previews the exact
name as you type and remembers what you set. Any prompt the assessment asks for
can be used as a token, plus `{assessment}`, `{date}` and `{source}` (the source
file's name):

| Token | Example |
|---|---|
| `{language}` | `Spanish` |
| `{window}` | `Trimester2` |
| `{year}` | `2026-2027` |
| `{assessment}` | `RunningRecords` |
| `{date}` | `2026-09-02` |
| `{source}` | the source file name, without its extension |

Spaces and characters a file name can't hold are removed, a token you leave out
doesn't leave a gap, and **Use Default** puts the standard pattern back. The save
dialog still opens, so you can override the name for any single run.

Files are saved Written as plain UTF-8 with
no byte-order mark, so eduCLIMBER reads the first header cleanly.

## Validation

Rows are flagged for an unrecognized or blank reading level, a blank Student ID, a
blank first or last name, and a combined student name that isn't in `Last, First`
form.

When something is wrong, a **review window** lists every affected row by its
spreadsheet row number — the number you see in Excel — with all of that row's
problems on one line. From there you can:

- **Skip those rows and continue**, exporting the rows that are fine. The saved
  file contains only the good rows, and the confirmation says how many were
  skipped.
- **Cancel**, fix the source file, and convert again.
- **Copy List**, to paste the issues into an email or work through them in the
  spreadsheet.

If *no* row could be converted there is nothing to export, and the window says so
rather than offering to continue. An invalid school year stops the run before any row is
read, and an unmatched column is asked about rather than failing. Completely blank
rows are skipped silently rather than listed —
and on an Excel file, row numbers still count them, so they match what you see in
Excel.

The same review window also shows **benchmark notices**, in amber, separate
from the red problems above — see [Benchmark scoring](#benchmark-scoring-proficiency-level).
Notices don't block anything and don't reduce what's exported; they open the
review window on their own so a Proficiency Level the app corrected is never
missed.

School year must match `YYYY-YYYY` exactly — no spaces.

## Project layout

```
Package.swift               open this in Xcode
Sources/
  EduClimberKit/            all the logic, no UI — this is what the tests cover
    Table.swift             loaded spreadsheet + loose header matching
    CSVReader.swift         RFC 4180 parsing, delimiter and encoding detection
    XLSXReader.swift        .xlsx via ZipArchive + SimpleXML
    ZipArchive.swift        minimal ZIP reader (Apple's Compression framework)
    SimpleXML.swift         XMLParser helpers for the workbook parts
    ColumnMapping.swift     match expected columns to real headers, rank suggestions

    RunningRecordsConverter.swift   source columns, field mapping, prompts
    ReadingLevels.swift     the Reading Level → Score table
    BenchmarkRubric.swift   rubric band matching (BenchmarkCell, BenchmarkBand)
    BenchmarkRegistry.swift the rubric tables + selection by language/school year
    CSVWriter.swift         the eduCLIMBER CSV
    Pipeline.swift          read → match columns → map → save
  EduClimberConverterApp/   AppKit UI
    MainWindowController.swift   the main window, built from the converter
    ColumnMatchSheet.swift       "which column is this?" sheet
Tests/EduClimberKitTests/   XCTest suite (`swift test` or ⌘U)
Resources/AppIcon.icns      the app icon (regenerate: python3 scripts/make_icon.py)
scripts/build_app.sh        builds and signs eduCLIMBER Converter.app
```

## Adding another assessment type

The shell (file picking, prompts, column matching, validation display, CSV export)
is assessment-agnostic. To add one: write a type conforming to `AssessmentConverter`
with its own `prompts`, `sourceColumns`, `outputColumns` and `convert(...)`, then add
it to the `converters` array in `MainWindowController`. It appears in the assessment
menu with its own prompts, and its declared `sourceColumns` get the same
auto-matching and "which column is this?" prompting for free.
